# My Account Dashboard Builder — project guide

WooCommerce **My Account** customizer plugin ( text domain `my-account-dashboard-builder`, prefix `acfw_` from its first name, Account Customizer for WooCommerce ). Repo: https://github.com/som3669/account-customizer-for-woocommerce.git ( `main` is the release line; feature work goes on a named branch first ).

Reference plugin (ThemeGrill commercial): `../customize-my-account-page-for-woocommerce` — UI/feature parity target (visuals similar, **not** a verbatim copy).

## Build pipeline (IMPORTANT — source of truth)

**Package manager: pnpm.** Build: **Gulp (`gulpfile.mjs`, ES module)** compiling SCSS→CSS + minifying JS.

```
pnpm install          # install toolchain
npx gulp build        # SCSS -> CSS (+ *.min.css) and JS -> *.min.js   (alias: pnpm build)
npx gulp watch        # rebuild on change
npx gulp zip          # build + package dist/my-account-dashboard-builder.zip  (pnpm zip)
```

- **Edit `assets/scss/*.scss`, NOT `assets/css/*.css`.** CSS is compiled output — direct `.css` edits are overwritten on the next build.
- Same for JS: hand-authored sources are `assets/js/{admin,frontend,design-studio,design-preview,view-as}.js` ( the `OWN_JS` list in `gulpfile.mjs`; add a new script there or it ships unminified only ); `*.min.js` are generated. `assets/js/block.js` is the Account Menu block's editor script, loaded as is; the block editor bundle builds from `assets/src/block-editor/` into `assets/build/` with `wp-scripts`.
- `assets/scss/_variables.scss` holds shared design tokens (`$accent`, `$border`, `$radius`, `$toggle-on/off`, …). SCSS vars feed the inline CSS custom props (`--acfw-*`) via `#{v.$var}`.
- Bundled libs are **not** built: `assets/css/fontawesome/`, `assets/{css,js}/select2/` ship as-is.

## Enqueue

`acfw_asset_src( $rel )` in `includes/helper/functions-acfw.php` resolves each asset to its `.min` build with a **filemtime** cache-buster. `SCRIPT_DEBUG` true → serves unminified sources. Used by admin, frontend, and customizer enqueues.

## Key files

- `my-account-dashboard-builder.php` — bootstrap, constants (`ACFW_DIR`, `ACFW_ASSETS_URL`, `ACFW_VERSION`).
- `includes/admin/class-acfw-admin.php` — top-level "My Account" admin menu + tabs (Menu Items, Design, Banners, Fields, Returns, Insights, Settings; Import/Export and Orders & privacy are Settings sections). `tab=templates` / `tab=customizer` land on Design. Banners uses the two-pane builder (left list + right detail); Menu Items is the menu canvas (see Conventions).
- `includes/frontend/class-acfw-frontend.php` — menu render, dynamic CSS vars, banners, avatar, redirects, status badges and the arranged dashboard.
- `includes/class-acfw-items.php` — default endpoints + icons (defaults are **FontAwesome** `fas fa-*` so the icon picker pre-selects them).
- `includes/class-acfw-design.php` — Design Studio registry ( `ACFW_Design::fields()`: every design option's group, type, default, bounds, `live` flag ), the per-user preview draft ( transient `acfw_design_draft_{uid}` ), the Studio AJAX endpoints, and preview mode ( `?acfw_preview=1`, shop managers only: `pre_option_*` filters serve the draft ). `includes/admin/tabs/class-acfw-tab-design.php` renders the Studio; `assets/js/design-studio.js` runs it and `assets/js/design-preview.js` runs inside the preview iframe.
- `includes/customize/class-acfw-customizer.php` — only a Customizer section linking to the Studio.
- `includes/helper/functions-acfw.php` — helpers: `acfw_asset_src`, `acfw_sanitize_color` (hex/rgba), `acfw_sanitize_icon`, `acfw_icon_list`, smart tags, visibility rules, order-tree helpers ( `acfw_order_insert`, `acfw_order_without`, `acfw_flatten_order_tree`, `acfw_order_logout_last`, `acfw_items_without` ), customer-field sanitizing / validation, `acfw_badge_text`, `acfw_offer_prefix`, `acfw_button_class`.
- Self-service and growth features, one class each, all instantiated in `includes/class-acfw.php`:
  - `class-acfw-stats.php` — `{prefix}acfw_stats` ( day, kind, ref, hits ), created by `maybe_install()` on `init` 5 ( `acfw_db_version` ). `bump()` is an upsert. Kinds: `view`, `banner_view`, `banner_click` ( the only one the `acfw_track` AJAX beacon accepts ), `offer_issued`, `offer_used`, `offer_revenue` ( cents ). Only logged-in non-managers count, and only with `acfw_track_views` = yes. Read by `tabs/class-acfw-tab-insights.php`.
  - `class-acfw-offers.php` — a banner's personal coupon: `coupon_for()` reuses the user meta `acfw_offer_{banner}` or issues one ( one use, email restriction, end of day N in the site timezone, meta `_acfw_offer` / `_acfw_offer_user` ). Managers get a `PREFIX-PREVIEW` code and no coupon. `?acfw_apply=` applies a code only for its own customer. Uses are counted once per order ( `_acfw_offer_counted` ).
  - `class-acfw-fields.php` + `tabs/class-acfw-tab-fields.php` — option `acfw_fields`, answers in user meta `acfw_field_{key}`; places `register` / `account` / `order` ( the admin order screen ). Smart tag `{field_key}` through the `acfw_smart_tag_value` filter. Exporter and eraser.
  - `class-acfw-returns.php` + `tabs/class-acfw-tab-returns.php` — cancelling ( `woocommerce_valid_order_statuses_for_cancel`, not shipped = not completed and no `_wc_shipment_tracking_items` ) and returns ( CPT `acfw_return`, not public; meta `_acfw_order_id`, `_acfw_items`, `_acfw_status`, `_acfw_reason`, `_acfw_comment`, `_acfw_photo`, `_acfw_reply` ). `set_status()` emails the customer through `WC()->mailer()`. On the order page the buttons live in WooCommerce's own Actions row when the located `order/order-details.php` calls `wc_get_account_orders_actions()`; `order_buttons()` then prints only the "until" notes.
  - `class-acfw-addresses.php` — user meta `acfw_addresses` ( id => label + `FIELDS` ), max 20, under the Addresses page and in a classic-checkout picker.
  - `class-acfw-privacy.php` — the `privacy` endpoint; `wp_create_user_request()` + `wp_send_user_request()`.
  - `class-acfw-profiles.php` — group menus in option `acfw_menu_profiles` ( slug => label, roles, order JSON, removed keys ). `apply( $slug )` filters `acfw_items_order` and `acfw_get_items` and rebuilds; on the storefront it runs at `wp` 5 for the visitor's first matching role, on the Items tab for `?profile=`. Every item also lives in the main menu: adding from a group menu adds it to both, limited in the main menu to the group's roles. `removed` remembers built-in items taken out ( they would come back as leftover defaults ). `endpoint_items()` registers endpoints only a group menu uses.
  - `class-acfw-nav-menu.php` — the Appearance → Menus box; `#acfw-account` / `#acfw-account-menu` custom links resolved on `wp_nav_menu_objects`. Classic themes only.
  - `class-acfw-compat.php` — icons for other plugins' account pages ( `acfw_default_icons` ) and the YITH / TI wishlist page.
- View as a customer: `class-acfw-view-as.php`. `ACFW_View_As::boot()` runs from the main plugin file ( before plugins_loaded, so no plugin resolves the user first ) and hooks `determine_current_user` at 100. A link ( `acfw_view_as`, `acfw_view_exp`, `acfw_view_key` = HMAC of manager|customer|expiry with `wp_salt( 'auth' )`, 2 h ) swaps the user only for the manager it was signed for, on front-end GET/HEAD page requests ( not admin, AJAX, REST, wc-ajax, cron ), never for staff ( `edit_posts` / `manage_woocommerce` ). A POST with the args is refused. While active: `guard()` refuses nonce / action args and the logout / payment-method endpoints, WooCommerce gets `ACFW_View_As_Session` ( in memory, `class-acfw-view-as-session.php` ), persistent cart off, `wc_current_user_is_active` removed, admin bar off, AJAX navigation off, `ACFW_Stats::counts_visitor()` false, `ACFW_Order_Stats` does not write its cache, `ACFW_Offers::for_viewer()` shows the customer's existing code or a placeholder and never issues one, avatar upload off. `assets/js/view-as.js` keeps the args on links inside My Account and stops forms and action links; the bar ( `render_bar()`, `hidden_report()` ) explains hidden items through `acfw_visibility_check()` + `acfw_visibility_reason()`. `ACFW_Design::is_preview()` / `draft_key()` use the real manager, so View as works inside the Studio preview. Pickers: `.acfw-view-as-select` ( select2, AJAX `acfw_view_as_search` ) trigger `acfw:viewas` with the signed URL.
- How to use guide: `includes/admin/class-acfw-guide.php` ( `ACFW_Guide::sections()`, filter `acfw_guide_sections`; `render( $tab )` prints the closed panel after the header, opening the section whose `tabs` hold the current tab ). The header's `.acfw-guide-toggle` opens it ( admin.js: focus trap, Escape, search ). Keep its steps in step with the features when they change.
- Status badges: `acfw_status_badges( $user )` ( memoised; filter `acfw_status_badges` ), shown by `ACFW_Frontend::status_badge()` in menu items ( template var `$status` ) and tiles; order = typed badge > status > count. Design option `acfw_status_badges` ( default yes ).
- Dashboard arrangement: design option `acfw_dashboard_layout` ( type `layout`, e.g. `stats,-welcome,…`; `acfw_sanitize_dashboard_layout()`, `acfw_dashboard_layout()` ). The frontend buffers WooCommerce's dashboard ( `woocommerce_account_content` 9 → `woocommerce_account_dashboard` -1000 = greeting, → 1000 = other plugins; content 11 is the fallback when a theme template has no hook ) and prints the parts in order, each `.acfw-dash-part[data-acfw-part]`. Hidden parts go to the Studio preview only ( `hidden` ), so design-preview.js reorders and shows them live. Parts: `acfw_dashboard_blocks()` ( filter ); a part prints via `acfw_dashboard_part_{key}` ( Commerce hooks tracking / buyagain there ). The Studio's layout rows own the `acfw_dashboard_stats` / `acfw_profile_meter` / `acfw_dashboard_tiles` switches ( `ACFW_Tab_Design::layout_options()` ), which are not drawn as controls of their own.

## Conventions / gotchas

- Design options are edited in the Design Studio and saved over AJAX, not through the Settings API group (registering design keys in the settings group wiped them on Settings save). Add a design option by adding it to `ACFW_Design::fields()`; mark it `live` only if `design-preview.js` can apply it without a reload.
- Icon fields: `icon_source` = `choose|upload`. On save, when `upload`, the `choose` FA class is cleared (and vice-versa) so a stale icon doesn't render.
- `[hidden]` attribute is overridden by `display:grid/flex` — hidden `.acfw-field`/rows need an explicit `[hidden]{display:none}` rule to actually hide (used for banner type/link conditional fields).
- Banner forms: two exist on the page (`__new__` create + each existing). Never emit duplicate element `id`s across them (broke `<label for>` radios) — buttonset wraps the input in the label instead.
- Color control = vanilla port of the reference React control: round checkerboard swatch → popover (native picker + opacity + hex), stores hex or `rgba()`. Banner colours go through `acfw_sanitize_color()` (not `sanitize_hex_color()`) so the alpha survives.
- Item keys: new keys come from `acfw_unique_item_key()` (ASCII, never a WooCommerce/WordPress/reserved name, never a key or slug already in the menu). Never run `sanitize_text_field()`/`sanitize_textarea_field()` on a key or on the posted order JSON: they strip `%xx` octets. Decode the order and pass it to `acfw_sanitize_order_tree()`; read posted keys with `sanitize_title()`.
- Custom endpoints need a `woocommerce_account_{key}_endpoint` handler, or `woocommerce_account_content()` prints the dashboard under them. `ACFW_Frontend::setup_endpoint_content()` adds an empty one.
- CSS tokens: the static fallbacks sit in `:where(.woocommerce-MyAccount-navigation.acfw-menu)` (zero specificity) so the inline design values (`.acfw-menu{…}`) win. Don't give the fallback rule real specificity again. The inline tokens are also declared on the dashboard widgets, banners and notice.
- Visibility rules (roles, dates in the site timezone, products, min / max orders, min spent, days since the last order) are evaluated by `acfw_visibility_passes()` for items and banners alike; it is the date check, the shop-manager pass, then `acfw_visibility_check()` ( which lists every failed rule with what was measured, for the View as bar ). Banners expose theirs through `ACFW_Banners::rules()`. `vis_max_orders` is stored as `''` when unset so `0` ( "no orders yet" ) stays a real limit: read it with `acfw_rule_max_orders()`, save it with `acfw_sanitize_max_orders()`.
- Settings API groups: `options.php` resets every option of a group that the posted form leaves out. The Orders & privacy section therefore has its own group, `acfw_settings_orders`. Give any new Settings section with its own form its own group.
- Storefront buttons use `acfw_button_class()`, which adds the block theme's `wp-element-button` class the way WooCommerce does; a plain `button` class looks unstyled in block themes.
- An admin handler that queues an `error` notice suppresses the generic "Changes saved." toast.
- Two elements use `.acfw-preview-frame`: the Banners tab's 108px preview box and the header Preview overlay. Scope overlay rules under `.acfw-preview-overlay`.
- Items tab detail pane: sections (General / Content / Visibility / Advanced) are ARIA tabs; select2 must be refreshed (`change.select2`) whenever a pane or section becomes visible, or multi-select placeholders measure 0px. `repaintClassicEditor()` rebuilds TinyMCE via `wp.editor.initialize()` and re-attaches the "Add smart tags" button.
- Menu Items canvas: `assets/scss/canvas.scss` compiles the storefront's `frontend.scss` scoped under `.acfw-canvas-page` ( `meta.load-css` ), and the tab adds `ACFW_Frontend::design_css()` inline, so the canvas shows the saved design. Rows keep the storefront markup ( `li.acfw-menu-item > a` or `> button.acfw-group-toggle` ); that link is the drag handle, and the row tools ( Duplicate, Delete, the switch ) sit in a grid column beside it. The click handler focuses the link itself: jQuery UI cancels mousedown on a drag handle, so it never gets focus otherwise and Alt + arrow moves have nothing to act on; `.is-pointer-focus` hides the keyboard ring for mouse focus. "Add to menu" posts the whole form ( `save_all` plus `acfw_add[...]` ): everything is saved first, then the item is appended ( `acfw_order_insert()`, which can also place it after an item or in a group ). Its dialog sits after the Save button in the DOM so Enter in a field still saves. Don't use `@container` in the SCSS: gulp-clean-css ( clean-css 4 ) drops the wrapper and applies its rules everywhere.
- Icon pickers print only the current option; the library is sent once as `window.acfwIconChoices` and searched by a select2 `ajax.transport`. Use `icon_picker()` for any new picker.

## Release / QA

- **Node 18+ required for block builds.** `pnpm zip` runs `wp-scripts build` (`@wordpress/scripts` ^30); on Node 14 it fails. Fall back to `npx gulp build && npx gulp zip` when only SCSS/JS changed, since `assets/build/` is committed.
- **`gulp zip` deletes the whole `dist/` folder** (`cleanDist`). Keep nothing there. Marketplace notes, screenshots and the demo seeder live in `submission/`, which the zip excludes.
- Lint gate: `vendor/bin/phpcs --standard=phpcs.xml.dist` ( 0 errors, 0 warnings ). `vendor/bin/phpcbf` fixes alignment and line endings.
- Unit tests: `vendor/bin/phpunit` ( 145 tests ). Brain Monkey, no WordPress: `tests/bootstrap.php` loads the helpers and the classes under test ( add a class there when a test needs it ), and `tests/unit/TestCase.php` stubs the core functions most helpers call. `__()` returns its argument; a test that reaches `_n()`, `wp_unslash()` and the like stubs them itself ( see `PreviewCustomerTest` ).
- CI ( `.github/workflows/ci.yml`, on pushes to `main` ): PHP syntax on 7.4–8.3, PHPCS, PHPUnit on 7.4 / 8.1 / 8.3, **translations up to date** ( it regenerates the POT and fails when strings changed without `languages/*.pot` being regenerated ), and the release zip ( `pnpm zip` ). So regenerate the POT in any commit that adds or changes a string.
- Line endings: this machine's git has `core.autocrlf` on, and phpcbf writes LF, so `git status` can list files that only changed line endings. Git normalises them on commit; `git diff --ignore-cr-at-eol` shows the real changes.
- Version: still 1.0.0 ( plugin header, `ACFW_VERSION`, readme `Stable tag` ). Everything since is under "Unreleased" in `readme.txt` ( grouped New / Tweak / Fix / Accessibility ) and `changelog.txt` ( `* New - …` lines, sorted New → Tweak → Fix ). A release renames both headings to the version, bumps the three version spots and adds an Upgrade Notice.
- `.pot`: `wp i18n make-pot . languages/my-account-dashboard-builder.pot --exclude=node_modules,dist,submission,assets/src`. wp-cli emits absolute Windows paths in the `#:` references here — strip the prefix afterwards.
- QIT: `qit woo:validate-zip <zip>` runs locally. The cloud suites (`run:security`, `run:phpstan`, `run:validation`, `run:plugin-check`, `run:phpcompatibility`) need the slug registered in the partner portal first; `run:activation`/E2E need WSL.
- `wp eval` works again on WP 7.1, but `wp db query` on Windows mangles `%` and quotes ( `LIKE 'acfw%'` silently returns nothing ). Run SQL with `%` through `wp eval-file` and `$wpdb`.
- Uninstall also drops `{prefix}acfw_stats`, deletes `acfw_return` posts with their photos and the `acfw_addresses`, `acfw_field_*` and `acfw_offer_*` user meta. Offer coupons are kept ( customers may hold them ).

## Testing in a real site ( without changing its data )

mas.test ( Laragon ) has real data, so browser and runtime checks run through a throwaway harness kept **outside the repo**, never committed and never left in the webroot:

- A boot file pre-seeds `$wp_filter` before WordPress loads: `option_active_plugins` turns WooCommerce and the plugin on for that request; `pre_option` / `pre_update_option` / `delete_option` / `add_option` keep every `acfw_*` option in a JSON store ( persisted only when asked, merged per request ); `determine_current_user` ( priority 99 ) picks the user; a transaction opened at `muplugins_loaded` is rolled back at shutdown.
- **A `query` filter must turn `CREATE` / `ALTER` / `DROP` / `TRUNCATE` / `RENAME` into `SELECT 1`**: DDL implicitly commits the open transaction, after which every later write in the request is permanent ( this once created `wp_acfw_stats` early ).
- `pre_wp_mail` records mail to a log instead of sending it; seed files run at `wp_loaded` inside the transaction for fixtures ( orders, return posts, user meta; fixed `import_id`s when a later form posts back to them ); an optional `query` logger lists INSERT / UPDATE / DELETE statements, the proof that a feature writes nothing.
- A token-gated PHP file in the webroot routes any page through that boot ( minting an auth cookie for admin pages ); Puppeteer ( `node_modules/.pnpm/puppeteer-core@*`, Chrome ) forwards page requests to it. Delete it from the webroot after each run.
- On admin pages wait for a fresh document ( a marker set before the click is gone ), not `networkidle0`. In Git Bash set `MSYS_NO_PATHCONV=1`, or `/my-account/` turns into a Windows path.
- Test accounts on mas.test: admin `1`, customer `1376` ( marianne, one completed order #100715 ), subscriber `5`. The site is a block theme ( gadgetix ) with the Checkout block, so the classic checkout picker and Appearance → Menus need a classic theme ( Storefront ) for that request.
- Logic that spans requests ( a coupon issued then used, a return requested then answered ) is easier to check in one CLI process: boot the same file, then `require wp-load.php`, act as a user with `wp_set_current_user()`, and throw from a `wp_redirect` filter to catch handlers' redirects.
- For FontAwesome checks, load pages over http ( same origin ); a `file://` page cannot load the webfont and shows tofu.
